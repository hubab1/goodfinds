# Recheck saved listings

Every scheduled search run checks previously saved listings as well as discovering new ones. After claiming the run and verifying the saved browser route, perform this pass before discovery. Manual searches can use the same pass when refreshing saved results.

1. Read `list_goodfinds_listings` with the saved `search_id`, `availability_check_before` equal to the run's `scheduled_at` (or `created_at` for a manual run), `include_dismissed: true`, `include_excluded: true`, `offset: 0` and `limit: 20`. Keep the default `availability: all`: reserved, out-of-stock, unknown and unexplained unavailable items need checks too. The queue omits confirmed sold, removed, expired and ended-unsold items. A current observation from another run satisfies the same check.
2. Open each returned canonical URL through the saved browser route. Apply the marketplace evidence rules below to the saved item; a retained description, photo or price does not establish availability. Keep the worker lease current and stop on cancellation, changed criteria or an access challenge.
3. Import each completed check with `import_goodfinds_listing_observations`, the current `run_id`, `worker_id` and a stable request UUID. Use `collection_stage: availability`, the returned `source`, `listing_id`, `url`, `product`, `provenance: manual`, the actual `observed_at`, `check_outcome`, and the observed `availability` plus `availability_text`. A successful check requires source wording. This status-only import retains saved facts, media, review coverage, first discovery and price history without refreshing their timestamps. Supply fresh facts in a separate discovery or verification observation.
4. Map explicit sold wording to `sold`, reservation to `reserved`, removal to `removed`, expiry to `expired`, and an explicit unavailable state with no known reason to `unknown_unavailable`. A usable purchase route or explicit available status can establish `active`; uncertain evidence remains `unknown`. A missing search result never establishes a sale. Login, rate limits, network failures and ambiguous not-found pages use the corresponding failed `check_outcome` and preserve the last successful status. Record a direct failed attempt rather than inventing an outcome.
5. Import the current page before requesting the next page at **offset 0**. Checks shrink the queue, so incrementing offsets would skip items. Continue until `total: 0`, even when enough new matches have already been found. Retain a bounded local set of attempted keys to detect a queue that fails to shrink; report that interruption rather than looping. A blocked route or unfinished pass leaves the run partial/blocked with the concrete next step. The server rejects scheduled completion while saved items remain unchecked.

Known terminal items remain in the Unavailable tab and keep their history. A later directly observed active status can reopen an item. A platform Sold label records marketplace availability; it does not confirm a purchase by this buyer or a final sale price.

## Marketplace evidence

Apply these rules during discovery and verification as well as scheduled rechecks. Read wording in the saved item's current detail page, including any selected size/model. Status on a recommendation, seller profile, favourite control or replacement listing belongs to that object. Preserve the actual wording in `availability_text`; the examples below are meanings to recognize, not guaranteed labels or selectors.

| Marketplace                     | Evidence and interpretation                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| eBay                            | Distinguish a listing sold to a buyer from a cumulative quantity-sold count. Check remaining stock for the saved variation: purchasable stock is `active`, explicit zero stock is `out_of_stock`. Use `ended_unsold` only when the page confirms no sale; an ended listing with no stated outcome is `unknown_unavailable`. Follow an observed relisting link as a separate identity when its item ID changes. |
| Facebook Marketplace            | Map item-level sold wording to `sold` and an explicit pending/reserved state to `reserved`. An explicit unavailable item with no reason is `unknown_unavailable`; a login wall or inaccessible-content error is a failed check. A Message button alone does not establish availability.                                                                                                                        |
| Vinted                          | Map item-level Sold to `sold` and Reserved to `reserved`. Use the item's current status and purchase controls; retained photos, prices and favourite-control feedback do not establish stock or removal.                                                                                                                                                                                                       |
| Gumtree                         | Preserve explicit sold, deleted/removed and expired outcomes separately. An unavailable ad with no stated reason is `unknown_unavailable`. A generic error or redirect to search remains a failed/uncertain check.                                                                                                                                                                                             |
| Craigslist                      | Distinguish explicit deleted/removed and expired posts from an item explicitly marked sold. A replacement or renewed post needs its own observed identity; disappearance or a generic not-found page does not establish a sale.                                                                                                                                                                                |
| Auto Trader UK (`autotrader`)   | Read the saved vehicle's current selling status. Explicit sold wording is `sold`; an advert explicitly no longer available without a reason is `unknown_unavailable`. Match the vehicle identity before using any linked dealer inventory evidence.                                                                                                                                                            |
| CarGurus US (`cargurus`)        | Scope status to the saved vehicle detail, not recommended cars. Preserve explicit sold versus unavailable wording. An inquiry button or redirect to replacement results does not establish that the original vehicle is available.                                                                                                                                                                             |
| Cars.com US (`cars_com`)        | Read status on the exact saved vehicle. Preserve sold versus unavailable outcomes. A Check availability form is an invitation to inquire, not confirmation; do not submit it as a check.                                                                                                                                                                                                                       |
| Autotrader US (`autotrader_us`) | Read the original vehicle's current status, preserving sold versus unavailable outcomes. Dealer contact/finance controls and suggested replacements do not establish stock for that vehicle.                                                                                                                                                                                                                   |
| Poshmark                        | Item-level Sold is `sold`. Not For Sale is `unknown_unavailable` unless the page explicitly establishes a reservation or another reason. Keep this item in future checks so it can become available again. Seller-wide sales totals do not establish the item's status.                                                                                                                                        |
| Depop                           | Distinguish item-level sold wording from a shop temporarily pausing purchases. Explicitly paused purchasing is `unknown_unavailable`, retaining the reason; recheck it on the next run. Check the saved size/variant rather than another available item.                                                                                                                                                       |
| Mercari US                      | Read the item-level status even when it appeared in search. Explicit Sold is `sold`; no longer for sale without a reason is `unknown_unavailable`. Use the saved US item identity and keep recommended items separate.                                                                                                                                                                                         |

For classified and vehicle sites, a current offer for the exact item with an asking price and seller contact route can support `active` when no unavailable wording is present. Record that visible offer as evidence. A generic contact form or retained advert fragment alone leaves availability `unknown`. Access errors use a failed `check_outcome`, preserving the last successful status on every marketplace.

Temporary-state guidance follows [eBay's stock and variations rules](https://www.ebay.com/help/default/default/multiquantity-listings-listings-variations?id=4150), [Poshmark's reservation guide](https://poshmark.com/posh_guide/how_to_reserve), and [Depop's Vacation Mode guide](https://depophelp.zendesk.com/hc/en-gb/articles/12267530258833-Vacation-Mode). These explain possible states; classify each saved item from its observed page.
