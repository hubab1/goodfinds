# Background work

## Dispatch from the buying chat

1. For a shared scheduled wake-up, follow [shared batch execution](scheduled-dispatch.md#execute-a-shared-wake-up): call `request_goodfinds_scheduled_batch` first and use its reserved runs. Do not request those runs again. For an unmigrated legacy wake-up, call `check_goodfinds_scheduled_search` with the prompt's search_id first. If `allowed` is false, return quietly without reading listing context, browsing or dispatching; do not catch up missed times. For a permitted wake-up or human request, read the latest installed skill and `get_goodfinds_search_context` for that scope. Reconcile the linked schedule during permitted scheduled work. A one-off request may check a paused search without changing monitoring.
2. For a human request or legacy wake-up, start/resume each scoped run with `request_goodfinds_search_run`, passing `request.trigger: "scheduled"` for an automation or `"manual"` for an explicit human search. If the server returns a disallowed `scheduled_check`, return quietly. If its phase is active and `worker` is present, reuse that worker: report saved activity only when useful and return. A new click or scheduled wake-up must not reset progress or launch an overlapping search.
3. Use the host's native subagent tool (`collaboration.spawn_agent`, or the host's equivalent), one collection worker per saved search. Apply the launch settings from `workflow.actions[].execution` and the generated [worker model routing](state-model.md#worker-model-routing). Pass the model, reasoning effort and context-fork choice as native launch arguments, rather than asking an already-running worker to switch itself. Supply the search/run IDs, a fresh UUID `worker_id`, absolute shared storage paths, installed skill path, saved browser route, current brief/query plan and any explicit buyer constraints. Preserve the buying chat's permissions. The worker verifies its own browser availability; parent access and another worker's limitation do not establish its access. Preserve the saved route; changing it requires the buyer's choice. The worker creates and closes only its own tabs.
4. Return a short acknowledgement after dispatch. Leave browsing, gallery review and polling to the child; the buyer can keep using this chat and the panel. Do not call a wait tool to occupy the buying chat until search completion. If native delegation is missing or launch fails, mark the unclaimed run blocked with the actual interruption and next step. A saved request alone stays queued, never “searching”.

The child prompt must tell it to follow the worker steps below and [search workflow](search-workflow.md), use the latest saved brief rather than stale chat criteria, preserve photo/video capture, and report terminal status even when interrupted. It must not dispatch further search agents. Collection workers save explicit evidence and return ambiguities or conflicts to the buying chat for judgment. Setup choices, final comparisons, schedule creation/changes and outgoing seller-message review/sends belong to the original buying chat.

## Recover interrupted searches

Separate a run's outcome from monitoring. A failed or expired worker leaves the buyer's enabled flag, recurring preference and host schedule intact. At the next permitted scheduled wake-up, resume unfinished coverage through the normal dispatch steps with a fresh worker. An explicit pause, cancellation or fulfilled goal remains authoritative; sign-in, access restrictions and browser-route choices need their own resolution.

During a live search, recover a transient timeout or disconnected tab once: reread the current run and brief, confirm ownership and eligibility, then retry the failed read-only step with the same worker. After lease expiry, the original buying chat may replace that worker once for the interrupted attempt, retaining the trigger and preflighting scheduled eligibility. Repeated failure saves the concrete blocker and returns; the next scheduled check may try again. Preserve successful queries, imports and media. Stable import request IDs prevent duplicate writes. Seller sends use their separate reconciliation workflow.

When the buyer opens Goodfinds or asks for progress, inspect interrupted runs alongside monitoring. For an already-authorized recurring search in its original buying chat, preflight scheduled eligibility and dispatch a due recovery automatically. A not-yet-due check waits for the existing schedule. Repair a removed or changed schedule only within the buyer's existing monitoring authorization, and preserve observed pauses. A saved one-off search needs a new search request after its bounded live recovery is exhausted.

## Execute in the search worker

1. Read the scoped context and run. Call `claim_goodfinds_search_run` with `request: {run_id, expected_version, worker_id, agent_id, parent_thread_id?, execution?}`. Use your actual native agent ID or canonical task name from the runtime. Report actual host-provided model/effort through `execution` as described in [worker model routing](state-model.md#worker-model-routing); leave unknown settings absent. Never invent an agent identity. The UUID distinguishes attempts; retain it throughout the run. On an ownership conflict, reread and stop if another live worker owns the run.
2. Renew with `renew_goodfinds_search_lease`: `request: {run_id, worker_id}` at least once a minute, before lengthy work, and after a slow tool returns. Claims last five minutes. Progress updates and run imports also renew the lease. Every progress update includes `worker_id` and the latest `expected_version`; every run import includes `run_id` and `worker_id`. Reread after imports, heartbeats or version conflicts.
3. Before every browser step and write, verify that the run remains active, your worker ID matches and the buying brief is unchanged. Scheduled heartbeats, updates and imports enforce current quiet hours and enabled/fulfilled state. A disallowed `scheduled_check`, deferred phase, cancellation, expired lease or changed brief stops this attempt. Preserve results and close your own temporary tabs. A stopped agent cannot revive its lease or write late run imports; resume through a new dispatch at a permitted time. Do not announce routine quiet-hour skips.
4. Verify that your native browser tools can control the saved route before discovery. If unavailable, record blocked status with the actual route limitation and return the needed buyer choice; leave other browsers untouched. An available Chrome bridge still requires observing the selected account's access and sign-in. API searches such as eBay do not require a browser. Then perform [broad discovery and shortlist verification](search-workflow.md), preserving platform permissions. Save useful observations incrementally, recover available photos/videos and review the required shortlist evidence. A heartbeat records activity, not query coverage or successful verification.
5. Save completed, partial or blocked status with evidence and a next step. Read prepared buying actions and return a concise result to the parent through the native agent completion channel. Notify only meaningful findings, failures or required buyer choices; routine activity belongs on the search row. For a scheduled run, record successful execution only after the actual search succeeds, preserving the linked schedule. Never mark execution successful at dispatch.

If the chat's exposed tool list predates these worker tools, use the latest installed [packaged protocol helper](connection-diagnostics.md#connection-diagnostics-and-fallback). Keep a single helper client across related calls so access-context identity remains stable. Do not rebuild an MCP client or change the buyer's browser to work around stale tools.

## Connection checks

1. Read `get_goodfinds_connection_check` for the requested `run_id`. For a direct buyer request, first queue the selected marketplaces using `start_goodfinds_connection_check` with the current settings revision and a fresh request UUID. Settings **Check** already queues the job and sends its ID to the buying chat. Reuse a running worker; return saved terminal progress without spawning. A queued job means no worker has claimed it yet.
2. The parent dispatches one native background subagent using the returned `execution.spawn` settings. Pass the exact run ID, current access context, targets, shared workspace paths, installed skill and supported browser tools. Return after dispatch; leave browsing and polling to the child. If delegation is missing or launch fails, reread the check and use `interrupt_goodfinds_connection_check` on an unclaimed queued job with its current `expected_version`, `status: unavailable` and the actual reason. Keep the main chat available; there is no foreground browser fallback, separate CLI/app-server launch or user-owned chat creation.
3. The child reads the exact check through the same connected MCP tool session. Confirm its `context_id` matches the current workspace `access_context`; a different helper/host connection cannot reuse that observation context. Claim with `claim_goodfinds_connection_check`, passing the current version, a fresh UUID `worker_id`, actual native `agent_id`, `parent_thread_id` when supplied by the host and known actual `execution` settings. The claim is required before browser work. A competing claim means reread and stop. Identities and settings are caller-reported audit information, not host attestation.
4. Renew using `renew_goodfinds_connection_check` at least once a minute and before/after slow browser steps. The lease lasts two minutes; each claimed check has a five-minute maximum. Before each browser step, verify that the check is still running, the worker matches and the selected route is unchanged. Stop on cancellation, expiry or a changed route; close only the tabs you created.
5. Use the child's actual browser capability inventory to control only the selected routes. When a device browser ID is unknown, establish the selected device default from observed host evidence; leave it unchecked if that identity cannot be established. Inspect only new tabs at the selected marketplace home pages. Record actual host/browser/profile identity and visible sign-in evidence; public browsing or a sign-in button alone does not prove signed-in access. Browser access and marketplace sign-in are separate observations. Leave passwords, cookies, tokens and account details in the browser. A check observes access only; sign-in, permission changes, challenges, listings and seller contact use their separate authorized workflows.
6. Reread/renew, then save paired observations using `complete_goodfinds_connection_check` with the owning `worker_id` and latest version. Omit unsupported targets; they remain unknown without refreshed evidence. If none can be checked, or execution fails, use `interrupt_goodfinds_connection_check` with that worker and the actual limitation. These check tools enforce ownership and cancellation; standalone browser/session report tools are not a substitute for completing a claimed check. Return a concise native completion result. Queued jobs expire after two minutes; late results cannot revive cancelled or expired work.

## Other actions

Delegate lengthy read-only contact, reply and media checks using the collection profile in [worker model routing](state-model.md#worker-model-routing). Pass existing action IDs and versions, preserve claim/cancellation checks, save the actual observations, then return a short result. Seller action claims also accept optional `execution` for known actual host settings. Keep scheduler changes, judgment and outgoing messages in the original buying chat with its model and reasoning and the existing exact reviewed draft/send permit. A request for background work does not authorize additional seller contact.
