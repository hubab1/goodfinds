# Broad discovery and shortlist verification

The buying chat dispatches through [background work](background-work.md) and returns. The steps below run in the claimed search subagent.

1. Read `get_goodfinds_search_context` for the assigned `search_id` and `run_id`. The parent has already requested the run; use that exact run ID and claim it with `claim_goodfinds_search_run` using your actual spawned agent identity and a fresh worker ID. Reuse a run already owned by you. If the supplied run is cancelled, fulfilled or belongs to a changed brief, record the interruption and return to the parent. Read progress before each update and use its `expected_version`.
2. Read query_plans.excluded_models and saved feedback before searching. Follow returned queries, which omit explicitly excluded models and documented aliases. Skip matching excluded search cards before deep inspection; retain category queries and do not suppress unknown models by title alone. Plan an exact name, documented aliases, brand terms, a broad category and relevant features/alternatives. Persist category_terms, query_plan and documented model_aliases in discovery. For espresso, include “coffee machine” and “espresso machine” early. Do not narrow every category query to the reference brand. Run a broad query before detailed seller/profile/photo work. Broad results still undergo exact-model and must-have rules.
3. Discover with search cards/title/visible full price and canonical IDs first. Import after each query with a fresh batch `request_id` (reuse its ID and exact arguments on retry), `run_id`, the claimed `worker_id` and `collection_stage: discovery`. Save visible thumbnails using [listing media capture](listing-evidence.md#capture-photos-and-videos-for-saved-listings). Record visible fields, incomplete image_review/video_review and unknown details. After provisional imports, read `list_goodfinds_media_repairs` for this search and capture ready photo/video galleries; do not restrict media saving to the shortlist. Save recovery through `attach_goodfinds_listing_media`, including partial/unavailable outcomes and the actual capture time. Resume missing media from earlier runs without changing old fact timestamps or their verification. Repeated sightings retain detailed evidence but require a fresh detail check before an alert. Do not guess setup costs, condition or gallery contents.
4. Update through `update_goodfinds_search_run`: `request: {run_id, worker_id, expected_version, query: <full returned query with updated status/counts>, phase, next_step}`. Record result_count and unique_relevant_count when known; deduplicate IDs across queries. Skipped/failed queries need a reason. Unknown count stays null. Newly discovered queries use add_queries with unique IDs, planned status and a selected marketplace.
5. Use the saved hard requirements and returned assessments to select a provisional shortlist for evidence collection. Buying judgment and product-tradeoff research stay in the buying chat under [worker model routing](state-model.md#worker-model-routing). Verify every gallery image and video, model identity, functioning, condition and model-specific essential accessories against the saved checks. Persist expected discovery.verification_checks as `{id, label, question}`. For manual espresso, check the correct portafilter, usable baskets and tamper; return model-specific research or ambiguous accessories to the buying chat. An integrated grinder may remove a separate grinder cost. A tidy photo does not establish a complete package.
6. Import details with `collection_stage: verification`, complete/partial image_review, video_review, media_capture and verification_checks. Source every confirmed or explicitly missing fact. Track required extras as setup_costs labelled observed/estimate/unknown, with currency and source. A missing part may be acceptable if replacements are allowed and the full setup fits. An unknown part remains a potential clarification, not a presumed replacement charge. Select seller questions through [message wording by stage](seller-conversations.md#message-wording-by-stage); retain the full checklist internally. Keep asking-price peers model-specific.
7. Complete the required [manufacturer-photo follow-up](search-covers.md) after provisional results or the initial discovery pass with no results. Resolve cover_follow_ups from search context: reuse a suitable photo or fetch, locally cache and attach an official manufacturer photo before finishing. Record a specific blocker if unavailable. Optional seller/profile/avatar enrichment gets one bounded attempt (about 10 seconds per download, 30 seconds total per listing). Failure retains unknown metadata and a note. Required seller-count limits still need evidence before final eligibility. Stop on access challenges and record the interruption.
8. Before final ranking or completion, run the [journey enrichment pass](journeys.md) for relevant saved listings with a travel requirement. Resolve each pending town with a cached or observed route, or record the specific access/location interruption. A visible town with no check is pending enrichment, not an unknown location. Set verifying for the shortlist, then completed only after all queries are completed or explicitly skipped and a broad category query succeeded. Completed query coverage does not mean exhaustive inventory: search_runs.pagination_complete remains independently truthful. Use partial/blocked with a next step for interruptions. Resume with saved outcomes and listing keys. Cancellation preserves saved listings and prevents further imports.

9. Read `list_goodfinds_next_steps` after completed/partial status. Collection workers return saved candidates, unresolved checks and prepared next steps to the buying chat. The buying chat compares candidates and presents the recommendation and saved exact opening message with review/send, choose another and keep searching choices. Continue through [buying follow-through](buying-follow-through.md), including chat when the panel is unavailable. Draft preparation is automatic and does not send anything.
10. Resolve the returned monitoring.next_action through [evaluation and delivery](evaluation-delivery.md). Reuse the buyer's established monitoring choice. If it remains undecided, offer search once versus keep watching after presenting the useful results. Requested recurring checks are complete only with a verified host receipt or an explained scheduling interruption; an initial one-off search does not silently activate a search.

Use `workflow.actions` and the generated [run states and guards](state-model.md#search-runs) to select or recover the next lifecycle step. Read views from `search_run_workflows[run_id]`; `allowed_actions` includes proposals that still require inputs. Satisfy the returned blockers and conditions; they grant no browser or sending permission. Keep one scoped brief in context; page summaries and fetch rich evidence on demand. Imports increment the run version, so reread compact runs before updating. Renew the worker lease at least once a minute and before lengthy work; check cancellation before every browser step and import. The panel searches for new scheduled runs even while idle, refreshes active work more often and pauses polling when hidden. Report query coverage, unique leads, unresolved checks and next step; routine reload instructions are unnecessary.
