# Buying follow-through

After a completed or partial search, read `list_goodfinds_next_steps` scoped by search_id. Finishing the saved run prepares an unsent opening message for the strongest suitable or conditional candidate. For older imports without a run, use `prepare_goodfinds_next_steps` with search_id. Preparation preserves edited drafts and existing conversations, creates no send action, and never contacts a seller.

Present the strongest candidate, why it is recommended, its asking price, any actual proposed offer and only material unresolved checks, then the exact prepared message. Apply [message wording by stage](seller-conversations.md#message-wording-by-stage) when selecting seller questions; the full verification checklist stays in the listing record. A small price-comparison sample limits value claims without blocking an enquiry. In the panel, expose the next message/reply action on its existing listing row; avoid a second list of the same candidates or repeated choose-another controls. Fetch `get_goodfinds_seller_conversation` for the selected listing before reviewing current wording. Check a contact route automatically when the buyer chooses that listing's message action, using the existing access and reviewed-send protocol. Draft preparation works before contact access is verified. Use the connected host action to run checks and searches; raw request prompts and copy/paste instructions do not belong in the buyer interface. An unavailable host connection produces a short connection message.

When the panel is unavailable, provide the same recommendation, exact message and action choices in chat. Use the packaged protocol helper if native tools are missing. Never replace a missing panel with repeated screenshots. A clear choice to send the displayed exact message authorizes creating its send action after current contact checks; “can you negotiate?” alone calls for a draft or capability check.

Read the attention queue to continue existing actions before proposing new outreach. An uncertain send needs reconciliation; counteroffers and seller questions need reviewed replies. Awaiting reply offers an explicit **Check replies** action. These checks are user-requested; background inbox monitoring is unavailable.

After agreement, read the conversation's collection_plan. Save known details with `save_goodfinds_collection_plan`, expected_version and plan: purpose viewing|collection, status draft|proposed|confirmed, when date/time/window/timezone or null, pickup_location, demonstration, evidence, seller_message_id and provenance user_reported|seller_message. Missing details remain null. Seller-message evidence must quote a saved incoming message; a confirmed plan needs a date, location and supporting evidence. Proposed buyer availability is not a confirmed appointment. Keep agreed price separate from asking price.

Use `prepare_goodfinds_collection_message` at the buyer's choice to replace the current draft with a message based on the saved plan and unresolved checks. Show its exact text for review; use the existing send action for dispatch. Confirm missing pickup details and necessary demonstrations without inventing buyer availability. Record **bought** only on the buyer's explicit confirmation, using set_goodfinds_buying_outcome. Its linked searches become fulfilled, leave the attention queue and reject further searches/outreach. Reopening the purchased conversation reopens the goal. Preserve other conversations and their history.
