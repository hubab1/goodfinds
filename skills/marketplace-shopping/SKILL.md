Read this installed entrypoint at the start of each new search. When `guidance_revision` differs from the version previously read, reload the references for the active workflow once; an updated entrypoint can point to changed reference files. Reuse those sections within the run rather than repeatedly loading them.

## Carry the buying request through

A request to find an item authorizes reading context, saving that brief, performing the supported search and setting up recurring monitoring in this buying chat by default. Use the saved cadence, defaulting to two hours, and honor an explicit one-off request or existing pause. Continue through routine reads, saves and recoverable tool errors in the same turn. End with useful results or one concrete blocker, not an announcement that the next setup step will happen later. Ask only for consequential missing preferences, a conflict with a newer user edit, or an action outside the authorized scope. Host tool-approval prompts are separate from conversational questions; explain them once if they interrupt progress and respect the host's permission settings.

Before promising discovery, inspect the selected marketplace/browser route. A working Goodfinds connection proves data and panel access, not browsing. For a direct single-platform search, use [search workflow](references/search-workflow.md). Read [background work](references/background-work.md) when delegation, scheduled execution or ownership recovery is needed. If no authorized execution route is available, save the supplied brief, explain the missing capability and give a concrete continuation. Queue work only when its executor can launch, using its actual agent identity.

Accept the latest explicitly stated city or area as the collection origin; it replaces an older saved origin without another confirmation. A city is enough to begin; describe the city-centre routing approximation in the recap and accept later refinements. Extract answers already given, including corrections and explicit no preference. Batch independent missing buying choices into one short question. Templates are adaptable starters: preserve the buyer's brief over template defaults.

Use one Goodfinds panel per buying chat. Before presenting a search or listing, follow [panel handoff](references/panel-chat-actions.md#show-the-search-at-the-right-time) to reuse an existing panel or display it once. `start_goodfinds_search` queues a manual run and requests that first display; after a panel has been shown, use `request_goodfinds_search_run` for further runs and reuse supplied active runs. Brief refinements, retries and result delivery keep the same panel. Continue executing or dispatching the returned run.

## Keep the buying chat available

Use native background subagents for multi-platform searches, scheduled work, connection checks and lengthy read-only browser actions through [background work](references/background-work.md). A queued run is not proof that an agent started. If no executor is available after a run is requested, record the interruption; preserve the selected browser route and saved results.

## Start with current monitoring

When opening Goodfinds or answering how saved searches are going, read `get_goodfinds_monitoring` before describing monitoring. Read scoped search context only when a brief or run needs attention. Its `monitoring` summaries include fresh linked Codex schedule observations; an enabled search or saved receipt alone does not prove an active automation. Present current results through the same panel handoff. If status is unverified, or a recurring search has no linked receipt, follow [scheduling and verification](references/evaluation-delivery.md#scheduling-and-verification) to inspect the actual host schedules and record the observed state. Preserve observed pauses. Repair monitoring within the buyer's recurring authorization. Prefer the original buying chat; an explicit Start checks, Resume checks or Restore schedule request permits the [removed-schedule recovery](references/scheduled-dispatch.md#recover-a-removed-schedule) fallback. A status check alone grants no new monitoring authorization.

Recover transient run interruptions through [search recovery](references/background-work.md#recover-interrupted-searches). An interrupted attempt keeps monitoring enabled. Each new scheduled occurrence starts fresh discovery; recovery within that occurrence preserves its saved coverage. Reserve paused status for an explicit buyer or observed host pause.

Keep intermediate browsing quiet. Prefer DOM/accessibility text for navigation, descriptions and seller/profile checks. Capture screenshots only for necessary visual evidence, using documented non-emitting options when inspection remains possible. Save listing photos and videos in the panel; give concise progress and final findings. Do not attach or re-emit intermediate screenshots, or call `emitImage` just to show progress. Required visual inspection still applies; follow [listing evidence](references/listing-evidence.md) for unavoidable host image output.

Follow returned `workflow.actions` availability, inputs, blocker recovery and worker execution profiles. Read the generated [state model and action guards](references/state-model.md) when a returned guard or recovery path needs explanation. Apply collection model settings at native worker launch; judgment stays in the buying chat. `requires_input` needs evidence or actor inputs; guidance never grants a send permit.

Persist edits with the target token from `revisions` and a stable request UUID. Read [tool contracts and persistence](references/tool-contracts.md) for draft promotion, conflicts, imports or interrupted calls. Read only the references needed for the current stage; workers load their own collection instructions.

## Choose the workflow

For a buying request, read current setup/search context before loading setup references. If a matching ready brief exists, go straight to Find listings. Load references by the active stage rather than concatenating every potentially relevant file; retain already-read sections. A saved cover with no pending follow-up does not require loading the cover guide. For a direct single-platform search, the search workflow below contains the run lifecycle; load background-work only when dispatch or recovery is needed. For vehicles, read [vehicle setup, filter readback, eligibility and price comparisons](references/vehicle-search.md) before setup or marketplace collection.

A request to find one item can finish with one fully verified suitable match. Cover the explicitly requested marketplaces and requirements, but do not keep searching optional sibling categories or alternatives after that need is met. Record unneeded planned queries as skipped with the actual reason; never report them as searched or empty. Requests for comparisons, several options or an audit require their wider scope.

- **Set up or edit:** read [search setup](references/search-setup.md). Use [adaptive interviews](references/adaptive-interviews.md) when consequential buying choices remain unknown. Extract existing answers first; ask only consequential missing details. Save the ready brief and show an editable recap. Apply the monitoring default or the buyer's explicit choice through [evaluation and delivery](references/evaluation-delivery.md). Cancellation preserves the draft.
- **Find listings:** read [search workflow](references/search-workflow.md). Before opening a marketplace, read its navigation guide: [eBay, Gumtree, Facebook, AutoTrader and Craigslist](references/marketplace-navigation.md), [Vinted clothing categories, filters and empty-filter recovery](references/vinted-clothing.md), [US vehicle sites](references/us-vehicle-marketplaces.md), or [Poshmark, Depop and Mercari](references/resale-marketplaces.md). The platform-selection reference does not replace these browsing instructions. Read [observation contract](references/observations.md) when preparing imports, not as a reason to defer opening the marketplace. Discover broadly before deeply verifying a shortlist. An exact-model requirement filters acceptance, not discovery vocabulary. Once results are ready, finish with the prepared next action in [buying follow-through](references/buying-follow-through.md) and resolve returned monitoring.next_action through [evaluation and delivery](references/evaluation-delivery.md), including after a partial search.
- **Draft or edit a seller message, contact, negotiate, arrange collection or check replies:** read [seller conversations](references/seller-conversations.md) and [buying follow-through](references/buying-follow-through.md). Apply [message wording by stage](references/seller-conversations.md#message-wording-by-stage) before composing or saving a draft. Every outgoing message uses a saved reviewed send action; a draft alone is not authorization.
- **Driving time missing, stale or near a travel limit:** read [journey checks](references/journeys.md). Check grouped towns through the chosen browser and save local route evidence before final eligibility.
- **Choose sources, access, location or feedback:** read [platforms, location and feedback](references/platforms-location-feedback.md). Browser availability, profile sign-in and listing contact are independent, scoped observations.
- **Monitor, pause, resume, remove or explain monitoring:** read [evaluation and delivery](references/evaluation-delivery.md). Reconcile in the original buying conversation, using [removed-schedule recovery](references/scheduled-dispatch.md#recover-a-removed-schedule) when an explicit start/resume request encounters a missing chat and deleted schedule. A development/review request describes or fixes the plugin; it does not authorize activating a buyer's search.
- **Change search hours or scheduled times:** read [search hours and timing](references/evaluation-delivery.md#search-hours-and-timing). Quiet hours default to 22:00–08:00 locally; respect them unless the buyer explicitly overrides. Each shared automatic wake-up starts with `request_goodfinds_scheduled_batch`; follow [shared scheduling](references/scheduled-dispatch.md) and preserve each search's timing.
- **Explain values or alerts:** read [evaluation and delivery](references/evaluation-delivery.md). Asking-price averages describe the observed sample.

## Shared data and tools

Tool discovery uses compact schemas so all actions fit the host's catalogue. Discover tools for the next action; print only names for a general inventory, and inspect detailed metadata for the selected tools. For an unfamiliar nested object whose fields are omitted, call `get_goodfinds_tool_schema` with its tool name once and retain the returned contract. Prefer the starter definition returned by setup for a new brief. Use connected MCP tools when available; the packaged CLI is a fallback for missing connections.

Manage settings, searches, listing filters, dismissals and buying conversations through the same MCP actions as the panel, including voice/text requests. Follow [panel and chat actions](references/panel-chat-actions.md) for the tool map. Use the shared mutation tools rather than editing stored files.

Read `get_goodfinds_search_context` for the brief, revision, discovery plan, feedback and access context. Use `list_goodfinds_listings` for paginated summaries and `get_goodfinds_listing` for shortlisted details. Read `list_goodfinds_media_repairs` before a media pass; save recovered files with `attach_goodfinds_listing_media` without refreshing old price/specification facts or review coverage. `list_goodfinds_search_runs` reads progress. `get_goodfinds_workspace` refills an already open panel without displaying it: its compact model summary is intentionally different from its complete app-only metadata.

Use bundled mutation tools so chat and panel share durable data. Use the scoped revisions and retry receipts in [tool contracts](references/tool-contracts.md); search progress and conversations retain independent version checks. Configuration and history share `workspace.sqlite` outside the installed plugin, under `~/.local/share/goodfinds/` or `GOODFINDS_WORKSPACE_DIR`. Use current tools or CLI export to inspect current searches. New workspaces start with the canonical SQLite schema. Sample data is isolated and fictional; never import it into live history.

If Goodfinds tools are absent, follow [connection diagnostics](references/connection-diagnostics.md). Use the packaged protocol helper instead of reconstructing an MCP client or changing host configuration without a concrete diagnosis.

For full-data deletion, follow [the scoped reset workflow](references/tool-contracts.md#delete-all-workspace-data). For every saved mutation and audit summary, follow [commit confirmation](references/tool-contracts.md#confirm-committed-work).

## Evidence and completion

Preserve uncertainty and contradictory evidence. Record explicit conflicts in verification_checks (state conflicting) or field_evidence; keep merely unseen or uncertain facts unknown. Contradictions rank below unconflicted candidates before price. Not seeing an accessory in a photo does not establish absence. Capture available photos and videos for all saved listings, including discovery thumbnails and missing media from previous runs. Inspect every available gallery image at readable size and view every seller video before claiming a completed verification; partial discovery imports are useful and remain ineligible for alerts. Follow [listing evidence](references/listing-evidence.md) for product identifiers, photo/video capture, review coverage and seller credibility.

Keep required suitability, evidence completeness and comparative value separate. Missing comparison dimensions do not establish unsuitability. Full setup costs include evidenced required extras; estimates and unknown costs remain labelled and cannot establish a verified within-budget deal. Keep model, condition, relevant bundles, currencies and rent periods separate in comparisons. Never loosen a must-have without the buyer’s choice.

A search is finished when its saved run accounts for query coverage, observations are imported, and the user sees useful results, the prepared next buying action and a clear monitoring outcome: one-off chosen, a verified host schedule, a concrete scheduling interruption or a monitoring choice still awaiting confirmation. Save results after each query. For identifiable products and clothing categories, complete the required automatic [manufacturer-photo follow-up](references/search-covers.md) at the start of the worker’s run, before marketplace discovery, including searches that later find no listings. Resolve returned cover_follow_up or cover_follow_ups before finishing; save the cached cover or report the concrete blocker. Optional avatars and profile enrichment remain bounded follow-up work. Recurring execution uses an available host scheduler; Goodfinds has no internal scheduler or notification transport.
